Idea flow — online: capture → card render

What happens between pressing ⌘/Ctrl+Enter in QuickCapture and a new IdeaCard showing up in the grid. The card is rendered once from the Zustand store: the local row is inserted first, then replaced in place by the server row when the POST returns.

client state IndexedDB / Zustand network revalidation / swap
1

Capture

keystroke → content string
  • components/ideas/quick-capture.tsx
    EditorX holds content state. Save via Mod+Enter or the ✓ button.
  • handleSubmit() clears the editor, closes it, then calls onCapture(content.trim()) fire-and-forget.
  • Dashboard / IdeasList pass create from useIdeas() as that handler — nothing is awaited in the UI.
2

Optimistic local persist

card is renderable immediately
  • hooks/use-ideas.ts → create(content). Effect runtime, AppLayer, resolves userId (session, else offline identity).
  • SaveIdeaLocally lib/outbox/idea-repository.ts → one Dexie txn writes two rows: db.ideas (CachedIdea, isLocal:true) and db.outbox (OutboxItem, status:"pending").
  • id = crypto.randomUUID() — a client id, not the DB id.
  • addPendingIdea(idea) → Zustand stores/ideas-store.ts inserts it into ideas and marks its id in pendingIds.
3

Server sync

if (isOnline)
  • POST /api/ideas with { content } — awaited inside the effect, errors swallowed.
  • app/api/ideas/route.ts: auth → createIdea() db/ideas.ts → 201 { idea }. source:"web", status:"inbox", pinned:false.
  • On res.ok: MarkSynced(id) deletes the Dexie idea and outbox row, then markPendingSynced(id, serverIdea) drops the local entry and inserts the server row.
  • No refetch is needed — the POST response carries the row, so the same card re-renders under its DB id.
4

Merge & render

the store feeds the cards
  • serverIdeas = data.ideas.map(normalizeIdea) — rows pass through lib/ideas.ts, then are upsertIdeas()-ed into the store.
  • selectIdeas({ ideas, pendingIds, status, search }) filters the store by status, drops the transient content dupe, and applies the search needle.
  • components/ideas/ideas-list.tsx splits into 3 columns (col(), lib/column-layout.ts), useAutoAnimate per column, maps <IdeaCard key={idea.id}>.
  • components/ideas/idea-card.tsx renders Markdown, source icon, relative date.

What the user actually sees

t0 — after submit
Dexie write + addPendingIdea land before the network call resolves. Inbox already has one item.
pending card · in pendingIds
t1 — POST in flight
Card shows client UUID as its key; content, “Just now”, and the globe (web) icon are already correct because the local row carries them.
same card, no visible change
t2 — res.ok
The local entry is replaced by the server row in the store under the new DB id. One commit, no refetch, no duplicate window.
server card · DB id
