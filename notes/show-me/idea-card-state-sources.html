Idea card render — the store is the single source

useIdeasStore holds every idea the client knows about. SWR is now only transport: its responses are pushed into the store and never rendered directly. Cards, the pinned tray, and the tabs all select from the store.

Zustand — single source SWR — transport only Dexie — full idea cache UI / chrome state
1

The store (source of truth)

stores/ideas-store.ts
  • ideas: Idea[] — every server row fetched + every pending local idea, newest first
  • pendingIds: Set<string> — which entries have not synced yet
  • queries — per-key size / hasMore pagination
  • loadedQueries — keys whose response reached the store (gates the skeleton)
  • cacheOutbox: QueuedCacheMessage[] — messages for the IndexedDB controller, acked once written
  • activeUserId / hydrated — owner of the list and whether IndexedDB has been merged in
  • isOnline
2

Transport

SWR — writes, never renders
  • use-ideas.ts builds the key from status, search, limit
  • useEffect on data → upsertIdeas(serverIdeas)
  • Same effect sets hasMore and marks the query loaded
  • Mutations PATCH then write the response idea back into the store
3

Disk

Dexie — cache of every known idea, plus the outbox
  • The store never touches Dexie. Each write queues an IdeasCacheMessage (upsert / replace / remove / clear) on cacheOutbox.
  • ideas-cache-controller.ts subscribes, writes the queue in one transaction, then acks the seq values it persisted. A concurrent flush waits rather than skipping.
  • SaveIdeaLocally still writes db.ideas + db.outbox together so a crash cannot orphan a local idea.
  • On mount/focus, hydrate(userId) flushes, then reads db.ideas + unsynced outbox ids and seeds the store.
  • Reload renders the cached list before any server round trip; synced rows live in the cache too, not only pending ones.
4

UI / chrome

Zustand + URL + local state
  • useUIStore → focusIdeaId, overlays, trays
  • useSearchStore → debouncedSearch (feeds store selectors + fetch key)
  • ?tab= via nuqs → which list is active
  • local: columnCount, editOpen, menuOpen, isUpdating, copied

From store to rendered list

// stores/ideas-store.ts — the only thing cards depend on
export function selectIdeas({ ideas, pendingIds, status, search }: SelectArgs): Idea[] {
  const needle = search?.trim().toLowerCase() ?? ""
  const syncedContents = new Set(
    ideas.filter(i => !pendingIds.has(i.id)).map(i => i.content)
  )

  const result: Idea[] = []
  for (const idea of ideas) {
    if (idea.status !== status) continue          // one slice per tab
    if (pendingIds.has(idea.id) && syncedContents.has(idea.content)) continue // transient dupe
    if (needle && !idea.content.toLowerCase().includes(needle)) continue
    result.push(idea)
  }
  return result
}

hooks/use-ideas.ts wires it up: const ideas = useMemo(() => selectIdeas({ ideas: storeIdeas, pendingIds, status, search }), …). Search is matched both server-side (fetch) and client-side (selector), so results are correct without waiting for a refetch.

Write paths — all end in the store

ActionStore writeThen
Create addPendingIdea(localIdea) POST → markPendingSynced(localId, serverIdea); stays pending offline
Archive / restore / delete upsertIdea({…idea, status}) (+ deleted_at) PATCH → upsertIdea(serverIdea); revert on failure
Pin / color / edit upsertIdea({…idea, field}) PATCH → upsertIdea(serverIdea); revert on failure
Permanent delete removeIdea(id) DELETE → re-upsertIdea(previous) on failure

Fetch / revalidate upsertIdeas(serverIdeas) + markQueryLoaded SWR is transport; data never rendered raw

Short version. One list lives in useIdeasStore. Fetches and mutations are the only writers. IdeasList and PinnedTray read through selectors, never from SWR. Pending ideas persist in Dexie and rehydrate into the store on mount and window focus.
Scope note. "Everything" means everything the client has loaded — the store accumulates each status as its tab is opened and grows with pagination. It does not eagerly download every page of every status on first paint.
